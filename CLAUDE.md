# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repository Is

This is a **prompt harness / agentic documentation framework** — not application code. It defines the process, contracts, context, and living documentation for building a multi-tenant SaaS logistics platform. The actual application code (`apps/`, `packages/`) does not exist yet and will be generated by following this framework.

The central principle: **documents don't describe the project, they drive it.** The agent must verify reality against documentation before every action.

---

## Mandatory Reading Order (every session)

Before touching any code or state, read in this order:

1. `AGENT.md` — the full agent contract (behavior, flow, limits)
2. `context/producto.md` — what is being built and for whom
3. `context/stack.md` — closed and pending technical decisions
4. `context/usuarios.md` — actors, permissions, and workflows
5. `doc/estado.md` — real-time state of sprints, features, DB, changelog
6. `doc/arquitectura.md` — **binding** technical rules (read the relevant sections before writing any code)
7. `doc/secuencias.md` — step-by-step prompt sequences per sprint

---

## Agent Execution Flow (no exceptions)

**Phase 1 — Context:** Read `context/` completely. Can you answer: what's the MVP? which stack decisions are closed vs. pending? who are the actors?

**Phase 2 — Clarify gaps:** If any decision in `context/stack.md` is "Pending" and it blocks the next step, stop and ask the human before proceeding.

**Phase 3 — Validate state:** Read `doc/estado.md`, then physically verify the repo (list folders, files, deps). Resolve any discrepancy in `doc/estado.md` first.

**Phase 4 — Confirm rules:** Read the applicable sections of `doc/arquitectura.md` for the step being executed.

**Phase 5 — Execute:** Locate/create the prompt in `prompts/`. Max 3 specific objectives per execution block. Verify empirically (build, lint, tests) — never declare success without evidence.

**Phase 6 — Sync docs:** Update `doc/estado.md` (use `skills/actualizar-estado.md`) and `doc/secuencias.md` (mark step ✅/🟡/⛔). Commit in English. **A task is NOT "done" until docs are synchronized.**

## Hard Limits

- **No `any` in TypeScript.** Use `unknown` + narrowing or generics. `as` casts require a `// SAFETY:` comment.
- **No secrets on the client.** `service_role` key is server-only, always.
- **RLS must be enabled in the same migration that creates a table.** No exceptions.
- **Types are generated, never written by hand.** Run `supabase gen types typescript --local > packages/types/src/database.ts` after schema changes.
- **No inventing state.** If it hasn't been read from the real repo, it doesn't exist.
- **No executing prompts** when the stack decisions they depend on are still "Pending" in `context/stack.md`.
- **Max 3 complex objectives per execution block.**

```
supabase/
  migrations/ # Versioned SQL: YYYYMMDDHHMMSS_description.sql
  functions/  # Deno Edge Functions
  seed.sql
```

Dependency graph is **unidirectional**: `apps/ → packages/`. Packages never import from apps. `apps/web` never imports from `apps/mobile`.

## Key Technical Rules (from `doc/arquitectura.md`)

### Supabase

- Browser client uses `anon` key + `@supabase/ssr` `createBrowserClient`.
- Server client (Server Actions, Route Handlers) uses `@supabase/ssr` `createServerClient` with cookies.
- Admin client uses `service_role` key — **never export to client-accessible modules**.
- Mobile client stores session tokens in `expo-secure-store` (never `AsyncStorage`).
- Every business table needs `id UUID`, `tenant_id UUID NOT NULL`, `created_at`, `updated_at` + `idx_{table}_tenant_id` index.

### Next.js

- `'use client'` only when component needs hooks, browser events, or browser APIs. Push it as low in the tree as possible.
- Mutations go through Server Actions or Route Handlers — not direct client-side Supabase calls.
- Always call `revalidatePath` / `revalidateTag` after mutations.
- Validate all env vars with Zod at app startup. Only `NEXT_PUBLIC_*` reaches the client.
- Use named exports (not `export default function`).

### Naming conventions

| Element | Convention |
|---------|-----------|
| TS utility files | `kebab-case.ts` |
| React components | `PascalCase.tsx` |
| Types | `TOrder`, `TDeliveryZone` |
| Interfaces | `IOrderService` |
| Enums | `OrderStatus.PENDING` |
| DB tables | `snake_case` singular |
| DB indexes | `idx_{table}_{columns}` |
| DB FK | `fk_{source}_{target}` |
| RLS policies | `{table}_{op}_{description}` |

### Migration workflow

```bash
supabase migration new <name>
# write SQL in supabase/migrations/YYYYMMDDHHMMSS_<name>.sql
supabase db reset          # apply locally
supabase gen types typescript --local > packages/types/src/database.ts
pnpm typecheck             # verify compile
```
