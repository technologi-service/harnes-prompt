# 🛠️ skills/ — Procedimientos reutilizables

> Una **skill** es un procedimiento paso a paso que cualquier rol puede ejecutar. Son las
> "recetas" del proyecto: se escriben una vez y se reutilizan en cada sprint para que el
> resultado sea siempre consistente.

## Skills disponibles

| Skill | Archivo | Para qué |
|-------|---------|----------|
| Validar estado | `validar-estado.md` | Comprobar la realidad del repo antes de tocar nada (anti-alucinación) |
| Actualizar mapa | `actualizar-mapa.md` | Sincronizar `doc/map.md` y `doc/sequences.md` al terminar (Metodología Viva) |
| Migración Supabase | `migracion-supabase.md` | Crear/cambiar esquema con RLS y tipos de forma segura |
| Nueva feature | `nueva-feature.md` | Flujo de punta a punta para añadir una funcionalidad |

## Reglas
- Las skills `validar-estado` y `actualizar-mapa` son **obligatorias** en casi toda tarea:
  la primera al empezar, la segunda al terminar.
- Si una skill se queda corta para un caso, se mejora la skill (no se improvisa por fuera).
